# Creator shops and the SuperNova collection

The public entrance printed on a contact magnet is `https://supernova2177.com/about`. About links to `/shop` and `/donate`. Every creator can turn on a profile shop from **My profile → Set up or manage my shop**. Only the account bound to the official owner ID controls the SuperNova collection. The permanent address of a released piece is `/pieces/{uuid}`. An archived or sold piece keeps its artist credit, image description, story, film, and links. Publish only works with clearance for that permanent display.

## Open the official shop first

1. Deploy the backend and frontend from the same change. The backend creates additive commerce tables in the app's database. Use separate databases, keys, webhook secrets and connected accounts for test and live deployments. Set the existing frontend `NEXT_PUBLIC_API_URL` to the matching API.
2. Identify the nonprofit-controlled profile by its immutable numeric harmonizer ID. Set `SUPERNOVA_SHOP_OWNER_ID` on the backend. Set `SHOP_SITE_URL` to the canonical HTTPS frontend origin for receipt and onboarding returns. On the frontend `SHOP_QR_ORIGIN` defaults to `https://supernova2177.com`; keep this enduring address for printed editions.
3. Enable Stripe Connect on the operator's Stripe account. Set backend `STRIPE_SECRET_KEY`. Add a **connected-account** webhook at `/commerce/stripe/events` for `account.updated`, `account.application.deauthorized`, `checkout.session.completed` `checkout.session.expired`, `charge.refunded`, `charge.dispute.created` and `charge.dispute.closed`. Set its signing secret as `STRIPE_CONNECT_WEBHOOK_SECRET`. Each seller finishes Stripe-hosted onboarding for a Standard account. Account and payout checks refresh in their dashboard. The nonprofit's seller account and payout bank must be organization-controlled.
4. In the shop settings enter the public seller contact, shipping estimates, return/damage terms and support arrangements. Set the Stripe Tax head office and applicable registrations for the liable account. A creator chooses a product tax code for each piece. Prices are USD. The first version supports one line and quantity one per checkout. Physical prices include US shipping. A digital file up to 10 MB stays in the private database and requires a verified paid receipt.
5. Set `SUPERNOVA_DONATION_URL` on the frontend to the nonprofit's verified Stripe donation Payment Link. Until configured, Donate opens the existing giving contact. Keep the free contact card outside inventory and avoid treating the price of a paid good as a charitable gift.
6. For an automatic private receipt and repeat download link, enable `SHOP_RECEIPT_EMAILS=1` on the backend and configure the platform's verified SMTP sender through `SMTP_HOST`, `SMTP_FROM`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD` and `SMTP_TLS`. Stripe retries a failed webhook. Duplicate events preserve the original inventory movement. Turn on payment and refund receipts in the responsible Stripe account. Store and transmit secrets through the hosting provider's secret settings.
7. Save a draft, review the credit, price, shipping promise, cover description and tax code. Attach the private file to a digital draft. Publish, then download its edition QR. For a SuperNova collectible magnet the stock is one. Reusing a shop's edition code is blocked. Check the artwork itself before release because an identical image can be given a different filename or code. The repeatable contact-card QR is available separately from settings and resolves to About.
8. Test a physical purchase, digital purchase, return to receipt, emailed receipt, full refund, disputed access, and two simultaneous attempts at the final copy in Stripe's test environment. Check the webhook delivery logs, payment and tax amounts, digital entitlement and payout destination. Live checkout still requires the live settings and merchant onboarding.

## Independent sellers

Leave `SHOP_MARKETPLACE_TAX_OWNER` unset for a nonprofit-only checkout pilot. Profiles can build shops and drafts. Before enabling third-party checkout, establish the operator, marketplace terms, rights and takedown contact, refund responsibility, any charitable or related-party arrangements, and which party must collect sales tax. Choose the matching operating model with the accountant. California's [Marketplace Facilitator Act guide](https://cdtfa.ca.gov/industry/mpfact.htm) explains the state rules. [Stripe Tax for marketplaces](https://docs.stripe.com/tax/tax-for-marketplaces) describes the payment configuration.

| Backend value | Charge and payout | Operating responsibility |
| --- | --- | --- |
| `seller` | Direct charge on each connected account. No platform fee is configured. | Seller configures Stripe Tax, sees the charge and handles refunds in Stripe. |
| `platform` | Destination charge on the platform. The seller receives the fixed merchandise subtotal, with shipping included. Exclusive tax stays on the platform. | Configure platform Stripe Tax, cover processing fees, handle disputes and refund/transfer reversals, and reconcile/remit tax. This is a business decision. |

For platform mode, also add an **own-account** webhook at `/commerce/stripe/platform-events` for completed and expired Checkout Sessions plus the three refund and dispute events listed above. Set its distinct signing secret as `STRIPE_PLATFORM_WEBHOOK_SECRET`. SuperNova's own listings continue to use its connected account. A change to the operating model affects new orders. Each existing order retains its processor context. Both models use Stripe-hosted card checkout. Revisit the operating model if seller jurisdictions require different tax responsibilities. Stripe credentials and accounts from one environment must stay paired with that environment's database.

## Order handling and a Redwood City stop

A transaction reserves one copy for up to an hour in Stripe Checkout. All visitors use the same SKU. The buyer can resume the original reservation in the same browser. Signed Stripe events confirm payment or restore an expired copy. A subsequent visit to a held piece also reconciles a missed expiry with Stripe. An uncertain processor response keeps the hold until it can be verified. A full refund or open dispute blocks digital downloads and physical fulfillment. Refund events update the seller’s order list. Inventory of a returned collectible requires human review. Do not reissue a sold one-of-one.

The seller's **Paid orders** view retrieves shipping or pickup details on demand and records fulfillment. Confirm the physical item, shipment or handoff and refund status in the responsible Stripe account before marking it fulfilled. Archiving or closing a shop stops fresh checkouts. Honor or explicitly expire any open Stripe Sessions issued beforehand. For the truck, the customer scans the same edition QR and pays on their own phone. This implementation needs connectivity and uses online Checkout. Card readers and offline sales require a different integration.

For an actual approved Redwood City event, set `SHOP_REDWOOD_PICKUP_LABEL` to the host, place, date and collection time, and `SHOP_REDWOOD_PICKUP_TAX_RATE` to the applicable exclusive Stripe Tax Rate ID on the official connected account. Confirm the rate for the items offered and the site. Set `SHOP_REDWOOD_PICKUP_END` to the ISO date/time of closing with its time-zone offset, for example `2026-12-12T16:00:00-08:00`. Mark only the pieces you will bring in the seller dashboard. New pickup checkouts close 31 minutes before the event ends so existing sessions can expire by closing time. Merchandise trucks need the city permit applicable to the stop. Verify the event and host before offering pickup. [Redwood City vendor guidance](https://www.redwoodcity.org/business/economic-development-special-projects/street-vending/vendors-vendedores)

## The collector's return visit

Print a dark edition QR on a clean light patch, with the human-readable domain and edition code below it. Place it on the backing card or visible face where a collector can reach it. Scan the physical print on two phones. Every paid piece leads back to the artist's permanent story, other editions, and the creator's social profile. Official pieces also offer a separate nonprofit support link.

For the first San Francisco magnet, use the real windowsill portrait and preserve Gugu's two feet and the skyline. For a shirt, translate her side profile and the skyline into a two-color graphic. Publish the medium and run size on each page so the one-of-one magnet promise stays precise. Pair a guest artist's small work with a captioned talk and written reproduction permission. Tell the story of the next stop on the existing social profile. Buyers can follow without another purchase.

The provider-specific operations are isolated in `backend/shop_stripe.py`. Keep the collectible ID, public story and order history when a second payment provider is added. A balance or wallet would be a separate product decision.
